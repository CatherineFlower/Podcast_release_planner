# Система планирования выпусков подкастов

Итоговая версия проекта для ПР3. Проект переведен с функциональной модели
ПР2 на объектно-ориентированную модель.

## Роли

### Администратор
Имеет полный доступ:
- просмотр всех подкастов, тем и выпусков;
- добавление подкастов и тем;
- добавление и изменение выпусков;
- удаление выпусков;
- просмотр общей статистики;
- просмотр и добавление авторов.

Тестовый вход:
- логин: `admin`
- пароль: `admin123`

### Автор
Автор числится во внутренней базе компании. Он не имеет доступа к
административным операциям и работает только в режиме чтения:
- видит свои подкасты;
- видит свои выпуски;
- видит статистику только по своим подкастам;
- отдельно видит опубликованные и неопубликованные выпуски.

Тестовые авторы:
- `anna / anna123`
- `ivan / ivan123`
- `maria / maria123`
- `alex / alex123`
- `elena / elena123`

## Объектная модель

Основные классы:
- `User` — базовый пользователь;
- `Admin` — администратор;
- `Author` — автор компании;
- `Podcast` — подкаст;
- `Topic` — тема выпуска;
- `Episode` — выпуск;
- `ReleaseStatus` — статус выпуска.

`Admin` и `Author` наследуются от `User`.
`Podcast` хранит объект автора.
`Episode` хранит объекты `Podcast`, `Topic` и `Author`.

## ООП в проекте

- наследование: `Admin` и `Author` наследуются от `User`;
- инкапсуляция: хеш пароля хранится в `_password_hash`;
- полиморфизм: `can_edit` работает по-разному для `Admin` и `Author`;
- композиция: `Podcast` и `Episode` содержат связанные объекты;
- `__init__` используется для создания объектов;
- `__str__` определяет удобный вывод;
- `@property` используется для вычисляемых свойств;
- `@classmethod` используется в `User.from_data()`;
- `@staticmethod` используется в `ReleaseStatus.values()`.

## Данные

В начальной базе:
- 1 администратор;
- 5 авторов;
- 10 подкастов;
- 15 тем;
- 67 выпусков.

JSON-файлы:
- `data/users.json`;
- `data/podcasts.json`;
- `data/topics.json`;
- `data/episodes.json`.

В JSON хранятся идентификаторы связей. При загрузке они преобразуются
в ссылки на Python-объекты.
